# Тематическая инструкция: wiki «Криптовалюты»

> **Как использовать:** объедините с общим шаблоном `00-template.md` — сначала вставьте шаблон (структура, конфиги, правила кодировки), затем эту тематическую часть. Скопируйте весь текст в новый чат MultiTool.

## Тема и назначение

Постройте англоязычную wiki-энциклопедию о криптовалютах, блокчейне и децентрализованных финансах — для разработчиков, инженеров и технических специалистов (не финансовых консультантов). Стиль — фактический, технический, как у нашей основной вики CoreStratum: у каждого инструмента/протокола своя страница с описанием, архитектурой и ссылками на официальную документацию.

## Важные предупреждения по содержанию

- Это **справочник технологий**, а не инвестиционный/финансовый совет. Не давайте рекомендаций «купить/продать», прогнозов цен или оценки «перспективности» монет.
- Указывайте технические характеристики (консенсус, TPS, время блока, язык смарт-контрактов), а не финансовые рейтинги.
- Помечайте статус проектов честно (mainnet/beta, активный/замороженный, open-source/проприетарный).

## Структура в трёх классах

### Theory (теория и концепции)

- **Blockchain fundamentals** — что такое блокчейн, блок, хеширование, Merkle-дерево, консенсус.
- **Consensus mechanisms** — PoW, PoS, DPoS, PoA, BFT, PBFT.
- **Cryptography in crypto** — криптография с публичным ключом, подписи (ECDSA, EdDSA), хеш-функции (SHA-256, Keccak/RIPEMD-160).
- **Wallets and keys** — горячие/холодные кошельки, сид-фразы (BIP-39), производные адреса (BIP-32/44), приватные/публичные ключи.
- **History** — краткая история от cypherpunk и e-cash до Bitcoin, Ethereum, DeFi, NFT.
- **Regulation basics** — кратко, нейтрально: правовые режимы, KYC/AML (без юридических советов).

### Tools (энциклопедия ПО и сервисов)

Каждая категория — список инструментов с отдельными страницами:

- **Node software (реализации протоколов)** — Bitcoin Core, Geth/Nethermind/Erigon (Ethereum), Solana validator, Polkadot, etc.
- **Wallets** — холодные: Ledger, Trezor, ColdCard; горячие/программные: MetaMask, Electrum, Exodus; кастодиальные онлайновые сервисы отмечать как таковые.
- **Explorers и аналитика** — block explorer (Blockstream.info, Etherscan, Blockchair), аналитика on-chain (Dune Analytics, Nansen).
- **DeFi-инструменты** — DEX и их движки (Uniswap, Curve), агрегаторы, ликвидные пулы, стейблкоин-протоколы.
- **Индексаторы и API** — The Graph, Alchemy/Infura, QuickNode.
- **Инструменты разработки** — Hardhat, Foundry, Truffle, Remix, OpenZeppelin, ethers.js/web3.js.
- **Майнинг и стейкинг** — сольные пулы (CGMiner, T-Rex), стейкинг-сервисы (Lido, Rocket Pool), валидаторы.
- **Мессенджеры/коммьюнити** — с осторожностью: это прикладное ПО, по нашей философии лучше отсылать на общие инструменты, а не вводить отдельные разделы (см. границу «инструмент vs контент» в шаблоне).

### Practice (практические руководства)

- Как запустить полный узел Bitcoin (`bitcoind`) и Ethereum (`geth`) — синхронизация, безопасность.
- Как создать кошелёк и работать с ключами (настройка hardware-кошелька, генерация мнемонической фразы).
- Как подключиться к узлу через RPC/JSON-RPC и сделать первую транзакцию из скрипта.
- Как развернуть смарт-контракт (Hardhat/Foundry) на тестнете.
- Настройка валидатора в PoS-сети (на примере тестнета).
- Безопасность: резервное копирование кошельков, изоляция ключей, аудит.

## Рекомендуемая структура доменов

```
docs/
├── sections/ (theory/tools/practice)
├── theory/        → категории: fundamentals, consensus, cryptography, wallets-keys, history
├── nodes/         → node software по сетям (bitcoin, ethereum, alt-сети)
├── wallets/       → hardware, software, custody
├── explorers/     → блокчейн-эксплореры и аналитика
├── defi/          → DEX, AMM, стейблкоины, ликвидность
├── dev-tools/     → фреймворки смарт-контрактов, библиотеки, API
├── staking-mining/→ стейкинг, валидаторы, майнинг-софт
└── guides/        → практические руководства
```

## Ключевые принципы содержания

- Каждая страница инструмента: `# Имя`, 2–4 предложения (что это, зачем), секция `## Key features` (если уместно), `## Resources` со ссылками на официальные сайты/доки/GitHub.
- Для страниц-протоколов указывайте: консенсус, токен, язык смарт-контрактов, лицензия, статус.
- Пометки для проприетарного: строка `**License:** Proprietary — not open source` (как в нашей вики).
- Все ссылки — только официальные; без ссылок на трейдинг-советы и сомнительные ресурсы.
- Английский язык, без эмодзи, без финансовых рекомендаций.

## Процесс

1. Возьмите структуру и конфиги из шаблона `00-template.md`.
2. Создайте TOC (index.md) с оглавлением всех доменов.
3. Наполняйте: сначала каркас (все категории с описаниями), затем страницы инструментов (можно партиями по категориям).
4. Прогоните чек-лист из шаблона: ссылки, front matter, кодировка, сборка.
5. Push на GitHub.
